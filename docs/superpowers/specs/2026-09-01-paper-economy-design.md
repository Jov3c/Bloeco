# Paper 经济系统（首版）设计

## 目标

为 Paper 1.21.11 单服务器提供一个以 SQLite 为权威账本、兼容 Vault 的统一货币系统。它必须让服务器收购有真实财政约束、让应税收入可追溯，并为后续通胀控制提供完整的数据。

## 范围与非范围

首版包含：单一货币、玩家余额、财政账户、发行与销毁、双式分录账本、配置化国库收购、对服务器收购的所得税、Vault Economy 提供者、管理员命令、玩家 GUI、审计与经济报表。

首版不包含：贷款、利息、银行账户、多货币、跨服同步、玩家间交易税的强制拦截、NPC 实体创建、拍卖行实现、自动动态定价。Vault 兼容的第三方交易在首版仅能改变余额；它们不会自动带上业务税种。

## 平台与依赖

- Paper 1.21.11，Java 21。
- Gradle Kotlin DSL。
- 标准 `plugin.yml`；`Vault` 是软依赖，未安装时核心经济照常运行。
- VaultAPI 仅以 `compileOnly` 方式引用；运行时由 Vault 插件提供 API。
- SQLite JDBC 使用 Xerial 驱动并打入插件 JAR。

## 货币与数值

内部金额一律以 `long` 保存，单位为 `分`，`100 分 = 1 元`。所有数据库金额、税率计算和账本金额均使用分；仅在 Vault `double` 接口、命令和 GUI 中格式化为两位小数。负数余额不允许。

货币显示名默认 `金币`、符号默认 `⛃`，均可配置。Vault 返回的任意 `NaN`、无穷数、负数或超过 `Long.MAX_VALUE / 100` 的金额都拒绝。

## 账户模型

系统账户固定为 `TREASURY`（财政账户）、`ISSUANCE`（发行账户）与 `BURN`（销毁账户）；每个玩家 UUID 对应一个 `PLAYER` 账户。

`ISSUANCE` 不是可花费余额，而是授权发行入口。管理员执行发行时，新钱进入 `TREASURY`，并产生 `ISSUE` 账本记录；发行账户允许作为无余额限制的特殊借方，且其累计净借方额就是累计发行。销毁时资金从来源账户进入 `BURN`，并产生 `BURN` 记录。`TREASURY` 的收入和支出只是在国库与玩家之间移动货币，不属于发行或销毁。

每一笔业务都写为同一 SQLite 事务中的不可变账本记录：交易 ID、时间、类型、借方、贷方、金额、玩家 UUID、备注。一个业务可产生多个分录（例如收购的毛款与税款），这些余额更新和全部账本插入必须同成同败。

## 收购与税收

管理员在 `procurement.yml` 配置收购项：Minecraft 材料、单次最多收购数量、每个物品毛价（分）、可用状态。玩家从 GUI 将背包中匹配物品出售给国库。

收购价格为毛价；应纳税额为 `floor(毛收入 × procurement-income-tax-rate)`；玩家实收为毛收入减税。国库先向玩家支付毛收入，再接收税额，因此其净支出为玩家实收。国库余额不足以支付毛收入时，整笔收购拒绝，物品不移除。

首版默认税率为 5%，仅适用于国库收购。玩家间转账及 Vault 第三方扣款/入账保留为 `VAULT_WITHDRAW` / `VAULT_DEPOSIT` 账本类型，不擅自课税。

## 玩家交互与管理员界面

- `/economy`：打开国库收购 GUI；显示可收购物品、单价、税率与国库可支付余额。
- 玩家点击收购项时，插件扫描其背包中该材料的数量，按单次上限结算；无匹配物、超过限额、国库不足或背包状态变化均给出明确提示。
- `/economy balance [玩家]`：查询余额。
- `/economy report`：显示流通玩家余额、国库余额、累计发行、累计销毁、近 24 小时收购支出与税收。
- `/economy treasury issue <金额> <备注>`：把新发行货币注入国库。
- `/economy treasury burn <金额> <备注>`：从国库永久销毁货币。
- 发行、销毁和配置重载仅允许 `centraleconomy.admin`。

首版不生成 NPC；管理员可将 `/economy` 绑定到 NPC 插件命令、菜单或告示牌。这样不绑定任何 NPC 实现，且交互仍是 GUI。

## Vault 兼容性

插件在检测到 Vault 后通过 Bukkit `ServicesManager` 注册唯一的 `Economy` 实现，优先级为 `Highest`。Vault 的玩家 `depositPlayer`、`withdrawPlayer`、余额查询和账户创建映射到同一 SQLite 账本。银行 API 返回“不支持”；世界参数忽略，实行全服统一货币。

为避免 Vault 调用隐式印钞：`depositPlayer` 的来源记为 `EXTERNAL_CREDIT`，`withdrawPlayer` 的去向记为 `EXTERNAL_DEBIT`。这两个项目会在报表中单列，并不会伪装为国库收入或支出。管理员必须确认任何外部插件的奖励机制都属于货币发行来源。

## SQLite 与可靠性

数据库位于 `plugins/CentralEconomy/economy.db`，启用 WAL、外键、`busy_timeout`。表包括 `accounts`、`ledger_entries`、`economy_daily_metrics`、`schema_version`。启动时创建/迁移 schema，关闭时关闭连接。

余额改动只执行带主键索引的短事务：读取受影响账户、验证余额、更新余额、插入账本、更新当日指标、提交。禁止在主线程执行全表统计和配置文件写入；报表读预聚合指标。首版面向单服，SQLite 事务优先保证正确性；未来跨服时以仓储接口迁移至 MySQL/MariaDB。

## 反滥用与可观测性

- 所有金额变动必须经过 `LedgerService`，禁止直接更新账户余额。
- 每次高权限发行、销毁与配置重载写服务器日志及账本备注。
- 收购先在主线程重新计数并临时移除准确数量的物品，再执行同一 SQLite 财务事务；若财务事务失败则立即恢复物品。这样不会出现已付款却未扣物的状态；库存恢复时因刚刚移除了对应数量，必然有槽位。
- 价格与数量限制由配置管理；不接受自定义 NBT 物品，避免变种物品套利。
- 每日指标记录新增/销毁、国库收入/支出、采购税、采购数量；后续 CPI 模块以真实市场成交数据接入，首版不伪造 CPI。

## 验收标准

1. 在 Java 21 的 Paper 1.21.11 上加载，`/plugins` 可见插件；未装 Vault 也可运行。
2. 安装 Vault 后，Vault 查询与其他 Vault 商店的存取款使用相同余额。
3. 所有失败操作不改变余额、账本、物品或指标。
4. 一次国库收购的玩家到账、税额、国库净支出、物品移除与账本完全一致。
5. 国库余额不足时不收物、不付款。
6. 单元测试覆盖金额转换、余额不足拒绝、双式分录、税收结算和 SQLite 回滚。
